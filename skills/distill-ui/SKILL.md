# Distill-UI:把设计系统需求蒸馏成 ui-skill

distill 的姊妹篇,同一种对话式元 skill,产出不同:distill 把方法蒸馏成 skill + blog,distill-ui 把设计系统需求蒸馏成 ui-skill。

本 skill 不含任何具体设计。五层是提问的地图,不是它的内容;配色、组件、原则,全部在对话中从需求方身上问出来。你不推荐配色,不裁决风格,只把对方的隐含判断问成显性规则。

## 管线

```
需求方加载 distill-ui → 对话沿五层 → 产出 ui-skill(他的设计系统)
→ 此后任何 AI 会话写界面 → 加载 ui-skill → token / 组件 / 规范即取即用
```

一致性边界 = ui-skill 的分发范围:发给谁,谁的 AI 产出就与源头一致。

产出即离场:ui-skill 铸出后,迭代、升级、提炼都在 ui-skill 内完成,不再回到 distill-ui。

## 对话规则

- 先听再问,一次只问一两个问题,不做访谈式轰炸(同 distill)。
- 逐层收敛:每层结束时用一两句复述该层产出,对方认同才进下一层;五层走完,整体蓝图确认,才动笔产出。
- 需求方可能带着已有规范来(旧文档、设计稿、现成代码、口头习惯、想对标的设计系统)——先读现状再问:把实际取值摆上桌让他对着确认,再收拢进五层,不推倒重来。
- 对方说不出某层内容时,给两三个具体选项帮他选;选项是梯子,决定仍由他做。选项用需求方的词写问句原文,不自造类目词。
- 问句要有主宾:谁、对什么对象、决策什么;待决策问题显性写出——没有待决策问题的问句是噪音。
- 对话深度在第一步定:不随项目规模,随使用方数量。

## 五层提问地图

### 第一步:使用方盘点(先于五层)

问:这套设计系统服务几个产品?只有需求方自己的 AI 用,还是同事、其他团队也会加载?一年内会变多吗?

使用方清单决定第四、五层的深度:单使用方,两层照走但收缩;多使用方,展开成全套。

### 一、设计原则

- 问:产品给谁用、在什么场合被使用?希望用户头三秒感受到什么?哪些事绝不做?两个设计打架时,你凭什么判?
- 合格线:3~5 条,每条都能裁决至少一个具体分歧。检验:出一道两难(如信息密度 vs 呼吸感),原则给得出答案。
- 字面免疫:原则说语义,不钉具体值——写"危险动作用危险语义色",不写"用红色";要管字面,就划值域:"危险色只在红色系取值"是原则,选哪个红是 theme 的事。
- 歪路:空话原则("简洁美观""体验优先"),什么都推不出来;原则互相打架,又没有优先序。

### 二、核心基础层

- 问:界面落在什么技术栈(CSS 变量 / Tailwind / 组件库主题)?要不要深浅色?品牌色从哪来?密度偏紧凑还是舒适?动效(时长、缓动)要不要约定?图标用哪一套、什么尺寸?
- 合格线:色彩、字型、间距、圆角、阴影各类 token 值齐、命名成体系、总量克制——起步求通,不求全;命名取语义(用途),不取字面(色号),换肤不锁死。
- 两级 token:字面档(red-500)供料,语义槽(--color-danger)供用;theme 就是对语义槽的一组命名赋值,不是另一套设计。有深浅色或多使用方,两级必须分开;单使用方且无深色,可塌成一级。
- 歪路:照大厂大全点菜,起步三百个 token。

### 三、组件与模式层

- 问:产品最先要做的三个页面或流程是什么?里面反复出现什么?组件要约定到哪层深度(状态、禁用、加载、空态)?表单、列表+详情这类组合有没有定式?
- 合格线:先行组件由真实页面反推;每个组件写明使用时机与禁用时机。
- 歪路:按组件库大全配齐;组件只画 happy path。

### 四、文档与知识层

- 问:谁会读这份文档——未来的同事?新人?最高频的查询是什么,某个 token 值,还是某组件怎么用?
- 合格线:双读者。AI 查任一 token / 组件 ≤ 一次跳转;人类能当规范通读,新人靠它上手。
- 歪路:只有机器速记,人读不懂;或长篇散文,AI 检索不动。

### 五、治理与运营层

- 深度随第一步:单使用方,记录一句话即可;多使用方,版本、变更、升级、审计四件齐。
- 问:允许不同产品锁不同版本吗?原则或 token 变了谁拍板、怎么通知?旧版本怎么升上来?怎么发现哪个产品漂了?
- 自升级(必答项):ui-skill 必须内置版本自省——被加载时核对使用方侧记录的版本,落后则主动告知变更,并引导或代为执行升级动作。治理不是文档里的一段话,是加载时的一个行为。
- theme 的边界:值域内换值、新增主题,低版本动作;改语义槽的含义或值域,是重设计,升主版本、走变更流程——theme 只能行政,不能修宪。
- 歪路:单使用方也全套治理;多产品锁着不同版本,却没有升级手册,1.0 永远漂着。

## 产出:ui-skill

文件结构、ui-skill 的 SKILL.md 骨架、版本与自升级机制,见 [references/ui-skill-spec.md](references/ui-skill-spec.md);落笔照 [references/templates.md](references/templates.md) 的模板填空,模板只有列名与占位符,没有真实设计。

产出前整体闸门:需求方对五层蓝图点头,才落笔。落笔从原则写起——原则约束以下各层,顺序不能倒。
